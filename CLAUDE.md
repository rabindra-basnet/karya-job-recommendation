# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Development
bun --bun run dev          # Start dev server on port 3000 (loads .env.local via dotenv-cli)
bun --bun run dev:b        # Dev without env loading (bare Vite)

# Build & run
bun --bun run build        # Build for production
bun --bun run start        # Run production build

# Database (Drizzle + Neon PostgreSQL)
bun run db:generate        # Generate migration files from schema changes
bun run db:migrate         # Apply migrations
bun run db:push            # Push schema directly (dev only)
bun run db:studio          # Open Drizzle Studio

# Testing
bun --bun run test         # Run Vitest suite

# Shadcn components
bun run ui add <component> # e.g. bun run ui add dialog
```

Environment variables go in `.env.local` (see `example.env` for required keys: `DATABASE_URL`, `GROQ_API_KEY`).

## Architecture

**Stack:** TanStack Start (SSR React on Vite) · TanStack Router (file-based) · TanStack Query · Drizzle ORM · Neon PostgreSQL · Better Auth · Groq AI · Tailwind CSS v4 · Shadcn/ui · Sentry

### Routing (`src/routes/`)

File-based routing via TanStack Router. The generated route tree lives in `src/routeTree.gen.ts` — never edit it manually.

- `__root.tsx` — root shell: injects CSS, Toaster, TanStack devtools
- `_auth/` — auth layout group (login, signup); `route.tsx` is the layout
- `_job/portal/` — main app:
  - `index.tsx` — paginated list of all recommendations (uses TanStack Query)
  - `create.tsx` — 3-step form to generate a roadmap
  - `$id.tsx` — displays a single AI-generated recommendation loaded via route loader
- `api/auth/$.ts` — Better Auth catch-all handler
- `api/recommendation.ts`, `api/getdata.$id.ts` — additional API routes

Layout groups (underscore-prefixed like `_job`, `_auth`) share a `route.tsx` layout but don't affect the URL.

### Server Functions (`src/server-fn/`)

TanStack Start server functions (`createServerFn`) run on the server but are called from client code. The main ones:

- `recommendations.ts` — `createRecommendation` (POST), `getRecommendationById` (GET), `getAllRecommendations` (GET)
- `system-prompt.ts` — exports `SYSTEM_PROMPT` used by the Groq API call

**AI recommendation flow:**
1. `create.tsx` collects user profile via a 3-step form using TanStack Form
2. On submit, calls `createRecommendation` server function
3. Server builds a prompt and calls Groq (`llama-3.3-70b-versatile`) with `response_format: json_object`
4. Response is validated against `aiResponseSchema` (Zod)
5. Everything is persisted in a single Drizzle transaction: one `careerRecommendations` row + related `careerPaths`, `skillGaps`, `learningSteps`
6. Returns the new recommendation ID; client navigates to `/portal/$id`

### Database (`src/db/`)

- `index.ts` — Drizzle instance backed by `pg.Pool`; uses `DATABASE_URL` from env
- `schema/career.ts` — main schema: `careerRecommendations` (parent) + `careerPaths`, `skillGaps`, `learningSteps` (children, cascade-delete). Enums: `work_style`, `learning_budget`, `demand_level`
- `schema/auth.ts` — generated by Better Auth CLI (`bun run schema:gen`)
- `schema/index.ts` — re-exports all schemas; this is what the Drizzle instance uses

Drizzle config (`drizzle.config.ts`) reads `.env.local`. Migrations output to `./drizzle/`.

### Auth (`src/lib/auth.ts` + `src/lib/auth-client.ts`)

Better Auth with Drizzle adapter. Email/password enabled. The `tanstackStartCookies` plugin wires cookie handling into TanStack Start. Auth schema is auto-generated — run `bun run schema:gen` after changing auth config.

### Styling

Tailwind CSS v4 (no config file; configured inline via `@tailwindcss/vite`). Custom CSS tokens use the pattern `var(--lagoon)`, `var(--sea-ink)`, `var(--palm)`, etc. — semantic color variables defined in `src/styles.css`. Shadcn components live in `src/components/ui/`.

### Error Monitoring (Sentry)

Configured per `.cursorrules`: wrap server function implementations with `Sentry.startSpan`:

```tsx
import * as Sentry from '@sentry/tanstackstart-react'

const myFn = createServerFn({ method: 'GET' }).handler(async () => {
  return Sentry.startSpan({ name: 'Description' }, async () => {
    // logic here
  })
})
```

Error collection is automatic via `src/router.tsx`.
